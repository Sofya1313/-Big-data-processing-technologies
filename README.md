# Геолокационные данные горожан и паттерны передвижения

Курсовая работа по дисциплине «Технологии обработки больших данных».

## Идея и границы исследования

Исходная тема работы — «Исследование геолокационных данных горожан для обнаружения паттернов передвижения и активности». Для практической реализации тема сужена до поездок **NYC Yellow Taxi**. Это обоснованное сужение, а не смена темы: каждая поездка содержит время, зону посадки и зону высадки, поэтому описывает перемещение по городу в обезличенном виде.

Объект исследования — городская мобильность Нью-Йорка, наблюдаемая через поездки жёлтого такси. Предмет исследования — пространственно-временные паттерны: где и когда возникают поездки, между какими зонами чаще совершаются перемещения, как меняются спрос, расстояние и стоимость поездок.

Координаты пассажиров и точек поездок в современном наборе TLC намеренно не публикуются по причинам конфиденциальности. Вместо них используются официальные идентификаторы **Taxi Zone**: `PULocationID` (зона посадки) и `DOLocationID` (зона высадки). Shapefile зон содержит их границы и геометрию. Поэтому географическая единица анализа — Taxi Zone, а не конкретный человек или адрес. Время анализируется на уровне даты и часа.

## Какую проблему решает работа

По отдельным строкам поездок трудно увидеть общую картину городской мобильности. Работа преобразует миллионы поездок в понятные показатели по месту и времени: спрос в зоне, популярные направления, среднюю дальность и стоимость поездок, а также связь этих показателей с дорожной обстановкой и городской средой.

Планируемые результаты дальнейших этапов:

- выявить типичные маршруты между парами Taxi Zone;
- определить часы и зоны повышенного спроса;
- сравнить характеристики поездок в разных зонах и временных периодах;
- оценить связь спроса с ДТП, обращениями 311 и транспортными событиями;
- подготовить признаки для дальнейшего прогнозирования спроса и поиска аномалий.

## Источники для пункта 2.2

1. **Реляционный набор — основной.** [NYC TLC Yellow Taxi Trip Records](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page), используется [файл за январь 2025 года (Parquet)](https://d37ci6vzurychx.cloudfront.net/trip-data/yellow_tripdata_2025-01.parquet). Поля: время, зоны посадки и высадки, расстояние, число пассажиров, способ оплаты и стоимость. Для расшифровки зон применяются официальный [Taxi Zone Lookup (CSV)](https://d37ci6vzurychx.cloudfront.net/misc/taxi_zone_lookup.csv) и [Taxi Zone Shapefile (ZIP)](https://d37ci6vzurychx.cloudfront.net/misc/taxi_zones.zip).
2. **Иерархический набор XML.** [NYC 311 Service Requests: описание набора](https://data.cityofnewyork.us/Social-Services/311-Service-Requests-from-2010-to-Present/erm2-nwe9/about_data), [XML API](https://data.cityofnewyork.us/resource/erm2-nwe9.xml?$limit=1000). Код выбирает до 1 000 обращений строго за январь 2025 года. При временной сетевой ошибке используется ранее сохранённая локальная копия того же январского XML. Обращения содержат время, тип проблемы, район и координаты.
3. **JSON API.** [NYPD Motor Vehicle Collisions: описание набора](https://data.cityofnewyork.us/Public-Safety/Motor-Vehicle-Collisions-Crashes/h9gi-nx95/about_data), [JSON API](https://data.cityofnewyork.us/resource/h9gi-nx95.json?$limit=1000). В анализ включаются ДТП строго за январь 2025 года.
4. **Неструктурированный текст.** [Архив пресс-релизов NYC DOT за 2025 год](https://www.nyc.gov/html/dot/html/pr2025/prindex-2025.shtml). Из архива программно отбираются официальные тексты, опубликованные в январе 2025 года.

Полная классификация всех атрибутов по аналитическим шкалам приведена в [`reports/attribute_scales_2_2.md`](reports/attribute_scales_2_2.md).

## Как данные будут объединяться

Наборы имеют разные единицы наблюдения, поэтому их нельзя механически склеить «строка к строке». Сначала каждый источник приводится к общим пространственным и временным признакам.

1. **Основа:** из Yellow Taxi формируется таблица на уровне `Taxi Zone × дата × час`. Например, для зоны посадки за конкретный час считаются число поездок, средняя дистанция, средняя стоимость и число пассажиров. Отдельно рассматриваются направления `PULocationID → DOLocationID`.
2. **Пространственная привязка:** у ДТП и обращений 311 есть широта и долгота. Их координаты будут сопоставлены с полигонами Taxi Zone методом пространственного соединения: каждой точке назначается зона, внутри которой она находится. Делать это вручную для каждой строки не нужно.
3. **Временная привязка:** ДТП и обращения 311 агрегируются по назначенной зоне, дате и часу. После этого их можно присоединить к основной таблице по ключу `Taxi Zone + дата + час`.
4. **Текстовый источник:** пресс-релизы DOT не имеют гарантированной точки на карте. Из них выделяются дата, упомянутый боро и тема. Поэтому они используются как городской или районный временной контекст и объединяются по дате, а при наличии явного боро — по `borough + дата`. Их нельзя искусственно выдавать за данные конкретной Taxi Zone.

Таким образом, общими признаками сопоставимости являются территория Нью-Йорка, время и административно-географическая принадлежность. Базовый набор отвечает на вопрос «как движутся такси», а остальные наборы описывают возможные факторы и контекст этого движения.

## Аналитический портрет

Для поездок ключевые категориальные характеристики — зона посадки, зона высадки, поставщик данных, тип тарифа и способ оплаты. Числовые — расстояние поездки, число пассажиров, стоимость, чаевые и итоговая сумма. Временные признаки — дата и время начала/окончания поездки.

Для факторов влияния используются категории ДТП или обращения, боро, статус, причина и тип транспортного средства; числовые показатели включают координаты, количество пострадавших, число обращений в зоне за час и длительность обработки обращения. Полное распределение **каждого** столбца по расширенным аналитическим шкалам приведено в [`reports/attribute_scales_2_2.md`](reports/attribute_scales_2_2.md).

## Как воспроизвести первый ноутбук

1. Установите зависимости: `pip install -r requirements.txt`.
2. Скачайте [Yellow Taxi Trip Records за январь 2025](https://d37ci6vzurychx.cloudfront.net/trip-data/yellow_tripdata_2025-01.parquet) и поместите `yellow_tripdata_2025-01.parquet` в `data/raw/`.
3. Скачайте [Taxi Zone Shapefile](https://d37ci6vzurychx.cloudfront.net/misc/taxi_zones.zip), распакуйте архив и поместите все файлы (`.shp`, `.shx`, `.dbf`, `.prj`, `.cpg`) в одну папку внутри `data/raw/taxi_zones/`.
4. Откройте `notebooks/01_data_sources_and_primary_profile_2_2.ipynb` в Jupyter Notebook или JupyterLab.
5. Выполните ячейки сверху вниз. Ноутбук сам получает небольшие выборки JSON и XML через официальные API и сохраняет их только локально.

## Пункт 2.3: очистка и объединённое хранение

Второй ноутбук — [`notebooks/02_preprocessing_merging_2_3.ipynb`](notebooks/02_preprocessing_merging_2_3.ipynb). Он запускает воспроизводимый конвейер из [`src/pipeline_2_3.py`](src/pipeline_2_3.py): очищает данные, назначает точечным событиям Taxi Zone, аннотирует и векторизует тексты NYC DOT, агрегирует данные и создаёт локальную Parquet-витрину `data/processed/fact_taxi_zone_hour_2025-01.parquet`.

Для обновления витрины без ручного выполнения ячеек используйте из корня проекта:

```powershell
python src/pipeline_2_3.py --month 2025-01
```

Подробное обоснование очистки, пространственного соединения, аннотирования текста, структуры хранения и результаты контрольного запуска приведены в [`reports/preprocessing_merging_2_3.md`](reports/preprocessing_merging_2_3.md).

Исходные наборы данных не добавляются в GitHub из-за размера и условий воспроизводимости. В репозитории хранятся ноутбуки, код, документация и история изменений.
