# Каталог источников для пункта 2.2

## Общая схема сопоставления

Территория исследования — Нью-Йорк. Единое временное окно практического исследования — **январь 2025 года**. Основной территориальный ключ — официальный идентификатор NYC Taxi Zone: `PULocationID` для зоны посадки и `DOLocationID` для зоны высадки. Основной ключ аналитической таблицы: `Taxi Zone × дата × час`.

## 1. NYC TLC Yellow Taxi Trip Records за январь 2025 года

- Тип: реляционный набор, CSV/Parquet.
- Назначение: основной набор для изучения поездок такси.
- Ссылка: https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page
- Пространственная привязка: `PULocationID` и `DOLocationID`.
- Категориальные признаки: `VendorID`, `RatecodeID`, `payment_type`, `store_and_fwd_flag`, `PULocationID`, `DOLocationID`.
- Числовые признаки: `passenger_count`, `trip_distance`, `fare_amount`, `tip_amount`, `total_amount`.
- Временные признаки: `tpep_pickup_datetime`, `tpep_dropoff_datetime`.

Ограничение: источник не содержит координаты или непрерывную GPS-траекторию отдельных поездок. Геометрия зоны получается из отдельного официального пространственного справочника Taxi Zones.

## Служебный пространственный справочник NYC Taxi Zones

- Тип: географический файл с полигонами зон.
- Назначение: связывает `PULocationID` и `DOLocationID` с названием зоны, borough и границами полигона.
- Использование: ДТП и обращения 311 по своим координатам относятся к полигону Taxi Zone, затем объединяются с поездками по `LocationID`.

## 2. NYC 311 Service Requests XML за январь 2025 года

- Тип: иерархический XML-набор, получаемый через официальный NYC Open Data API.
- Назначение: фактор состояния городской среды. Из API выбирается до 1 000 обращений строго за январь; в анализ оставляются транспортно значимые категории. При временной недоступности API используется сохранённая локальная январская копия XML.
- Ссылка: https://data.cityofnewyork.us/Social-Services/311-Service-Requests-from-2020-to-Present/erm2-nwe9/about_data
- XML API: https://data.cityofnewyork.us/resource/erm2-nwe9.xml
- Пространственная привязка: `latitude`, `longitude`, `borough`, `incident_zip`.
- Категориальные признаки: `complaint_type`, `descriptor`, `agency`, `borough`, `status`, `open_data_channel_type`.
- Числовые признаки: `latitude`, `longitude`; дополнительно рассчитываются час создания, время обработки обращения и число обращений в зоне. `unique_key` используется только как технический идентификатор записи.
- Время: `created_date`, `closed_date`.

## 3. NYPD Motor Vehicle Collisions API за январь 2025 года

- Тип: API с ответом JSON.
- Назначение: ДТП как фактор аномальной длительности и интенсивности поездок.
- Ссылка: https://data.cityofnewyork.us/Public-Safety/Motor-Vehicle-Collisions-Crashes/h9gi-nx95
- API: https://data.cityofnewyork.us/resource/h9gi-nx95.json
- Категориальные признаки: `borough`, `zip_code`, `contributing_factor_vehicle_1`, `vehicle_type_code1`, улицы.
- Числовые признаки: `latitude`, `longitude`, число пострадавших и погибших, число пострадавших пешеходов/велосипедистов.
- Время: `crash_date`, `crash_time`.

## 4. Архив пресс-релизов NYC DOT: публикации января 2025 года

- Тип: неструктурированные текстовые данные в HTML-страницах официального сайта.
- Назначение: дорожные работы, изменения организации движения, безопасность, перекрытия и иные транспортные события как контекст городской мобильности. Из годового архива программно отбираются только материалы с датой публикации в январе 2025 года.
- Ссылка: https://www.nyc.gov/html/dot/html/pr2025/prindex-2025.shtml
- Категориальные признаки: тип документа, тематическая категория, упомянутый borough, месяц публикации.
- Числовые признаки: длина заголовка, длина текста релиза, число транспортных ключевых слов в тексте.
- Время: дата публикации релиза.

Текст связывается с другими данными на уровне borough и даты, если в материале указан район. Если место не указано, текст используется как городской контекст даты и не искусственно привязывается к конкретной Taxi Zone.

## Аналитические типы шкал

Тип хранения поля не равен типу аналитической шкалы. В частности, `PULocationID`, `DOLocationID`, `LocationID`, `collision_id` и `unique_key` хранятся числами, но являются номинальными идентификаторами. Они применяются для соединения источников и подсчёта частот, но не усредняются.

В исследовании используются расширенные типы шкал. Номинальная ID применяется к идентификаторам записей и зон. Категориальная шкала применяется к коду поставщика, способу оплаты, району, типу обращения, причине ДТП и тематике текста. Дихотомическая шкала представлена `store_and_fwd_flag` со значениями Y/N. Порядковая шкала будет использоваться для рассчитываемой тяжести ДТП: нет пострадавших, есть пострадавшие, есть погибшие. Интервальная шкала применяется к датам и времени. Шкала отношений применяется к расстоянию, стоимости и длительности поездки или обработки обращения. Абсолютная шкала применяется к числу пассажиров, поездок, обращений, пострадавших и транспортных слов. Контентная шкала применяется к тексту пресс-релиза, заголовку, URL и исходному полю JSON с координатами.
